# voice-lora-detect：中文 AI 味与文风检测

## 元数据

- **类型**：Tool / Classifier
- **适用场景**：用户询问中文 markdown 文章的“AI 味”浓度，最有 AI 味的段落有哪些，这篇文章有没有可能是鸭哥（yage.ai）写的等
- **目标读者**：AI Agent（指导其在用户提问时安装依赖、运行命令、解析分数、规范汇报）
- **代码入口**：`voice-lora score`
- **默认分类器**：`src/voice_lora/data/classifier-v1.1.json`（随 Python 包分发，约 0.55 MB）
- **模型规格**：字符 1–3 gram TF-IDF + 逻辑回归，保留权重最大的 10,000 个特征 + 300 个 AI 腔词。纯 JSON，加载时不执行任何代码。

## 它量的是什么

分类器输入一篇 markdown 文章，输出这篇文章“像鸭哥（yage.ai）写的”的概率 P(作者)（0 到 1 之间）和命中的 AI 腔词。

文章得分是各个正文段落分数以段落长度为权重的加权平均。标题、引用块、表格、代码块和少于 20 字的块不计入。

### 为什么能用来判断中文 AI 味

分类器的训练目标是区分鸭哥博客的原文和 AI 改写的文字（开源 27B、Gemini 3.8 Flash、DeepSeek V4.1 Flash）。训练数据用成对的样本，原文和改写说的是同一件事，模型只能学习措辞差异，而不是学话题词。

测试显示，这个分数基本上衡量的是“离鸭哥有多远”。它可以判定 AI 味，是因为 AI 写的文字离鸭哥比任何真人作者都远：
- 鸭哥的博客文章的中位数在 0.945 左右；
- 其他人的真人文章的中位数在 0.561 左右，集中在 0.35–0.80；
- 常见的 LLM（包括训练时没有见过的 GPT-6 Astra、Claude Sonnet 5、Kimi K3）生成的文章大部分低于 0.30。

分类器对训练中未出现的模型家族在文章级区分真人和 AI 的 AUC 达到了 0.93–0.98，并能识别 AI 起草、人修订过的文章（AUC 0.981）。因此，它可以作为一个中文文本 AI 味的自动评分器。

## 什么时候用，什么时候不用

### 适合使用
- 快速初筛中文 markdown 文章的 AI 味分布。
- 找出文章中 AI 腔最重、拖累自然度的具体段落及命中的 AI 腔词。
- 比较同一篇文章修改或重写前后的文风变化。

### 禁止使用
- **判定某人“是否用了 AI”**：绝不能用于学生作业、投稿审稿、招聘筛选等定性场景。测试中 11% 的真人文章低于 0.3，存在误判。
- **核对内容真伪**：分类器只看字词与表述，对虚假事实、逻辑错误或篡改立场完全无感知。
- **对抗场景**：文字可以被刻意改到高分，用同一批数据训练的改写模型也会天然迎合它，所以它不适合当对抗场景下的检测器。
- **单段文本定性**：单段方差极大，绝不能只看单段分数。
- **判断“像不像我写的”（除非用户就是鸭哥）**：随包分类器以鸭哥为参照。别人想知道像不像自己，需要用自己的文章训一个分类器（见模型卡“用自己的文风训一个”）。

### 慎用（分数要打折看）
- **新闻稿、编辑过的媒体稿**：体裁用语（如“据……报道”“报告显示”）在训练集中几乎只出现在 AI 那一侧，这类文章的分数会偏低。校准测试里分数最低的真人文章（0.10）就是一篇行文规整的媒体稿。

## 安装与命令

### 1. 安装方式
```bash
uv pip install git+https://github.com/grapeot/voice-lora     # 或者在仓库里 uv pip install -e .
```

### 2. 常用命令
```bash
voice-lora score article.md other.md                          # 每篇一行：P(作者)、判断、AI 腔词/千字、段数
voice-lora score article.md --paragraphs 3                     # 再列出分数最低的 3 段，以及它们命中的 AI 腔词
voice-lora score *.md --json                                   # JSON，按从最像 AI 到最像作者排序
```

## 怎么读输出

### 1. 只看文章级，不看单段
单段噪声很大。在测试中，其他作者撰写的真人段落里，仅 54% 的段落得分高于 0.5（即近半数真人段落低于 0.5）。因此绝不能凭借个别段落得分直接定性整篇文本，必须以文章级加权得分为准。

### 2. 默认分档标准
分界线来自模型卡的校准实验：

| P(作者) | 判断 | 含义与经验分布 |
|---|---|---|
| < 0.3 | AI 味浓 | 校准测试中 92% 的纯 AI 文章落在此档，AI 起草经人工修订的文章有 98% 低于 0.3 |
| 0.3–0.5 | 灰区 | 真人与 AI 文章均有分布，不能单凭数字下结论，必须由人通读上下文判断 |
| 0.5–0.85 | 像真人写的 | 其他作者的真人博客多数在这一档（中位数 0.561，最高 0.80） |
| ≥ 0.85 | 接近作者本人 | 鸭哥本人博客文章中位数为 0.945；其他真人作者文章最高未超过 0.80 |

### 3. AI 腔词/千字的作用与局限
该指标仅用来辅助解释是哪些高频词拉低了段落分数（排在前面的有：借助、笔者、鉴于、此前、极为、依据、具体而言、随后、应对、此类、显著的、具备、开展、上述、未能等）。
**切勿单独用 AI 腔词率判断 AI 味**。在校准测试里，用 AI 腔词率区分真人文章和 DeepSeek 写的文章，AUC 只有 0.525，接近随机。

### 4. 样例输出解读
真实运行输出样例：
```text
| 像鸭哥写的概率 | 判断 | AI 腔词/千字 | 段数 | 文件 |
|---|---|---|---|---|
| 0.031 | AI 味浓 | 9.36 | 14 | ai_draft.md |
| 0.399 | 灰区 | 8.19 | 35 | human_blog.md |

```
- **`ai_draft.md`（得分 0.031，判断为“AI 味浓”）**：分数远低于 0.3，低分段落出现“应对、即为、未能、依然、并未”等典型 AI 腔词，符合 AI 起草特征。
- **`human_blog.md`（得分 0.399，判断为“灰区”）**：这是 2019 年阮一峰写的真人博客，分数落在 0.3–0.5 的灰区。它分数最低的两段，一段 0.01（命中“难以”），一段 0.03（一句民调数据）。这说明单段分数低不代表是 AI 写的。
- **灰区处理原则**：**真人博客也完全可能落在灰区**。一旦文章落在灰区，Agent 必须明确告知用户该区间兼具真人与 AI 可能性，严禁直接判定为 AI，需人工结合语义通读。

## 参数怎么调

| 参数 | 默认值 | 什么时候改与权衡取舍 |
|---|---|---|
| `--bands a,b,c` | `0.3,0.5,0.85` | 更怕漏掉 AI：把第一条线提到 0.35–0.40（代价是误伤更多真人，0.35 误伤 17% 真人，0.40 误伤 33% 真人）；更怕冤枉真人：把第一条线降到 0.25（94% 真人高于线，82% AI 低于线）。 |
| `--paragraphs K` | 0 | 想知道是哪几段、哪些词拉低了分数时设为 3–5。 |
| `--min-paragraph N` | 20 | 文章里有很多短句、口号、小标题短语或图注时调高，避免短块左右文章加权均分。 |
| `--classifier FILE` | 随包版本 | 使用自己训练或指定的分类器 JSON 文件。 |
| `--config CONFIG` | 无 | 从该次运行的数据现训一个分类器。 |
| `--json` | 关闭 | 输出机器可读的结构化 JSON，按从最像 AI 到最像作者排序。 |

## 怎么向用户汇报

Agent 完成检测后应这样向用户汇报：
1. **文章得分与分档**：文章级 P(作者) 分数为 X，属于 [分档] 档（如 0.031 → 【AI 味浓】，0.399 → 【灰区】）。
2. **最低分段落与命中词**：`--paragraphs 3` 给出 3 个最低分段落片段及其命中的 AI 腔词（如“未能、依然、并未”），解释这些措辞如何产生生硬感。
3. **局限与边界**：仅反映统计措辞倾向，非定论。若为灰区，注明“真人文章也可能落入灰区，建议人工通读”；若为新闻体裁，提示可能存在体裁偏低偏差。

## 局限与禁止事项

- **不能用来判定某人用了 AI**：不能当作学校作业作弊、投稿退稿或招聘定性的铁证。它只反映措辞倾向，存在误判（测试中 11% 的真人文章低于 0.3），且不同写作者文风差异显著。
- **看不出内容对错**：编造的引语、删掉的论点、改掉的立场，只要措辞像，分数照样高。不可作为真实性审计工具。
- **会被刻意迎合**：用同一批数据训练的改写模型会天然朝它喜欢的方向走，文字也可以被刻意改到高分，不具备对抗检测能力。
- **有些 AI 文章会偏高**：校准测试里，心理、个人成长类题目的 AI 文章最高到 0.45；刻意模仿人类风格的 prompt 写出的 AI 文字没有测过。
- **体裁偏差**：以个人博客为参照，新闻综述、公文报道中的固定套路词（如“据……报道”、“报告显示”）在训练集中多偏向 AI 侧，媒体稿分数会偏低。
- **不同版本的分数不能混比**：分类器随训练数据变化（v1 仅用 27B 改写训练时作者均值为 0.86；v1.1 完整版为 0.76；精简版为 0.86）。升级分类器后必须重新测试基准，切勿直接跨版本比对分值。
